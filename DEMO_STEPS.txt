SIGNAL ATLAS
CRIMINAL NETWORK INTELLIGENCE PLATFORM
WINDOWS DEMONSTRATION GUIDE
====================================

This file contains the complete local demonstration procedure for the Signal Atlas MVP.

The demonstration uses fictional synthetic data only. It does not contain real police,
intelligence, financial, location, or person records.

The system is designed to demonstrate evidence traceability, role-based access,
graph analysis, human review, and grounded AI assistance.


1. WHAT THIS DEMONSTRATION PROVES
=================================

The demonstration should show that:

1. An administrator can authenticate.
2. An administrator can create, edit, archive, and merge reviewed entities.
3. An administrator can upload evidence.
4. Extracted information enters a review queue instead of becoming an automatic fact.
5. Relationships can point back to evidence.
6. An analyst can search and explore a graph.
7. The graph supports cycles, many-to-many links, and multiple relationship types.
8. Graph analytics can identify structural metrics.
9. Timeline and geographic views can be filtered.
10. Analytical signals are presented as review prompts, not legal conclusions.
11. The assistant answers from stored graph and evidence records.
12. Reports include evidence references and system limitations.
13. The auditor can inspect an append-oriented activity trail.
14. Analysts cannot modify core source data through the backend.
15. Every important action is logged.
16. Camera sources stream independently and are controlled by role.
17. Face detection produces evidence-backed observations, never automatic identity.
18. A human reviewer decides whether an observation is associated with a Person.

The correct presentation is:

    Observed: A relationship exists in a source-backed graph.
    Derived: The relationship creates a measurable structural pattern.
    Analytical: The pattern warrants analyst review.
    Not established: Criminal liability, intent, or guilt.

21. CAMERA MONITORING AND VISUAL EVIDENCE
========================================

This module performs face DETECTION only. It does not identify anyone.

The system never creates face embeddings, never matches faces, and never has a
biometric watchlist. A camera detection is stored as an observation. A Person
association is written to the graph only after an authorized human reviewer
selects a Person in the review queue.

Optional preparation, in a PowerShell window while the backend is running:

    .\scripts\setup-camera-demo.ps1 -DemoMode -Start

This registers three independent sources:

    Demo Camera 01 - Main Gate     WEBCAM index 0                      Main Gate
    Demo Camera 02 - Parking       VIDEO_FILE demo-parking.mp4          Parking Area
    Demo Camera 03 - Entrance      VIDEO_FILE demo-entrance.mp4         Building Entrance

If CNI_CAMERA_DEMO_MODE=true is set in .env, the interface shows a persistent
banner:

    DEMO SIMULATION MODE - NOT BIOMETRIC IDENTIFICATION

CAMERA SOURCES (Admin only)

Open:

    http://127.0.0.1:5173/admin/cameras

Show:

1. Add a camera with source type, source URI, location, and timezone.
2. Start and stop an individual source.
3. Edit the configuration.
4. Archive a source.
5. Show masked stream URIs so embedded credentials are not exposed.
6. Show that the Analyst role sees no mutation controls.

LIVE MONITORING

Open:

    http://127.0.0.1:5173/monitoring

Show for each camera:

1. Live annotated frame.
2. Bounding boxes around detected faces.
3. Detection count and total observations.
4. Connection status and last frame timestamp.
5. Location and camera name.
6. That one stopped or failed source does not stop the other sources.
7. That no person name is ever drawn on the frame.

Explain:

    "The box means a face-shaped region was detected. It does not mean the system knows
    who the person is."

Note for the presenter: the bundled synthetic clips contain a drawn subject that
the prototype detector does not classify as a face. Real detection requires a real
face. Use the webcam, or set a VIDEO_FILE camera to an MP4 that contains a person.
The synthetic clips still demonstrate independent multi-source capture, evidence
storage, cooldown throttling, review, and graph integration through demo
simulation events.

A WEBCAM source records real imagery from the machine. Only point it at yourself
or at a consenting subject, and delete the captured frames after the
demonstration.

DETECTION REVIEW

Open:

    http://127.0.0.1:5173/monitoring/review

Show:

1. The pending observation list with camera, time, and location.
2. The annotated evidence image with the bounding box.
3. Camera ID, location, timestamp, and detector metadata.
4. Detection confidence. The prototype uses a binary Haar cascade, so the
   interface shows "Not scored by binary detector" rather than inventing a
   percentage.
5. Duplicate throttling. A continuously visible face produces one event per
   cooldown window, not hundreds.
6. Mark invalid.
7. Verify observation.
8. Search for an existing Person and associate it manually.

Explain:

    "The reviewer is comparing the camera evidence with the record set. The software
    does not compare faces."

Explain:

23. FRESH RESET FOR A REPEATABLE DEMO
=======================================

Only use this when you want to delete local demonstration data.

First stop the backend and frontend processes.

Then run:

    Remove-Item backend\data\cni.db -Force -ErrorAction SilentlyContinue
    Remove-Item backend\storage\uploads -Recurse -Force -ErrorAction SilentlyContinue

Restart the backend:

    .\scripts\start-backend.ps1

The application will recreate the synthetic seed case on startup.

Warning:

    These commands delete local SQLite data and uploaded files. Do not run them against
    a real investigation database.

27. WHAT MUST NOT BE INFERRED
==============================

The system must not claim that:

- A person is guilty.
- A person is a criminal.
- A relationship proves criminal intent.
- A high-degree person is an offender.
- A location is a crime scene.
- A transaction is illegal.
- A missing coordinate can be guessed.
- An extracted candidate is trusted before review.
- An AI answer is factual without citations.
- An analytical signal is a legal conclusion.
- A detected face identifies a person.
- A simulated demo event is a real biometric match.

Use this wording:

    "The graph shows this relationship."
    "The analytics show this structural position."
    "This pattern warrants review."
    "The evidence record supports the stored relationship."

Avoid this wording:

    "The system knows this person is criminal."
    "The AI proved guilt."
    "This entity is an offender."

29. OPTIONAL CSV IMPORT
=======================

The Windows helper script is:

    .\scripts\import-synthetic.ps1

Or use the Admin API:

    POST /api/v1/imports/csv

The importer:

1. Accepts UTF-8 CSV files.
2. Stores the source file as evidence.
3. Creates entity records where appropriate.
4. Creates candidate relationships where source and target IDs are present.
5. Marks the import as review-required.
6. Records a CSV_IMPORTED audit event.

Imported relationships are not silently treated as fully trusted.

    cd frontend

    .\scripts\start-frontend.ps1

    Invoke-RestMethod http://127.0.0.1:8000/api/v1/health

Frontend check:

    Invoke-WebRequest http://127.0.0.1:5173

    .\scripts\verify.ps1

    .\scripts\evaluate.ps1

If a local database is corrupted, stop the servers and use the fresh-reset procedure in
section 23 only after confirming that the data is disposable.
